## F-1 (красная). Негативный контроль line-endings красный

Воспроизведение:

```
bash lab/selftest-guards.sh line-endings
  ok    the attack suite notices a planted wrong expectation
  FAIL  line-endings: a CRLF shell script was NOT caught
controls passed: 1   failed: 1
RESULT: fail                                  # код 1
```

Полный прогон: `controls passed: 10 failed: 1`. `guards.yml` вызывает этот же скрипт (строка 53).
Следствие в приборе готовности: `python tools/fg_readiness.py` печатает `E1 ... 0` и
`tier: T0 — nothing runs` при ядре 83 % и общей 50 %.

Причина найдена и проверена отдельно, а не выведена из текста. Контроль `lab/selftest-guards.sh:126-136`
кладёт файл lab/_negative_crlf.sh в подготовленную копию и **не коммитит его**. Страж
`lab/check-line-endings.py` перечисляет файлы через `git ls-files`, то есть видит только
отслеживаемые. В копии:

```
plant не добавлен в git  -> files with CRLF or a parse error: 0,  RESULT: ok   (код 0)
после git add -A         -> lab/_negative_crlf.sh: CRLF,          RESULT: fail (код 1)
```

То есть страж ловит CRLF, как только файл отслеживается, а контроль проверяет неотслеживаемый файл.
Это не только поломанный контроль: докстрока стража говорит, что «рабочее дерево может быть
неверным, пока тесты идут», но `git ls-files` это дерево не читает; CRLF в новом, ещё не
добавленном скрипте проходит зелёным.

Два варианта правки, выбор — ваш, потому что они проверяют разные вещи:

1. **Страж читает и неотслеживаемые файлы:** `git ls-files --cached --others --exclude-standard`
   (одна строка). Тогда контроль начинает проверять ровно то, что обещает докстрока;
   `--exclude-standard` убирает `target/` и подобное.
2. **Контроль коммитит посадку** после `printf` (как это уже делает контроль secrets). Тогда
   проверяется только отслеживаемый CRLF, и докстроку стража надо сузить до этого.

Цена первой правки — один аргумент команды; вторая — две строки в контроле. После любой из них E1
возвращает 10 баллов, ядро становится 60/60, общая 60 %, а уровень — T1 (E1, E2, E6). Сейчас один
неотслеживаемый файл стоит уровня.

правка — обновить четыре числа; устойчивая — либо убрать числа из прозы, либо добавить счётчик,
который краснеет на расхождении (шаблон такой посадки у вас уже есть в selftest).

## F-3 (красная). Страж цитат красный на двух исторических упоминаниях; CI падает здесь раньше selftest

`python lab/check-artifact-refs.py` на `c06d28b` без этой заметки даёт `dangling: 2` и код 1;
с первым черновиком заметки было `dangling: 4` — две были наши, мы их убрали. Оставшиеся две —
ваши и существовали до нас:

```
dangling  lab/experiments/E-M43-hostile-doc-review.md: tools/_tmp
dangling  lab/experiments/E-M76-external-audit.md: tools/_tmp
```

Оба упоминания — исторический пересказ («records were scanned … including tools/_tmp» и «the step …
against tools/_tmp/m13.json»), а не утверждение, что артефакт есть. Каталог в `.gitignore`, поэтому в
чистом клоне его нет и не будет. `.github/workflows/guards.yml` запускает этот страж на строке 45,
до selftest (строка 53), значит job красный уже здесь, и F-1 не единственная причина.

Правка: либо убрать обратные кавычки вокруг исторического упоминания (цитата прошлого не обязана
быть путём), либо добавить allowance с причиной — но тогда правило «allowance, чей путь теперь
существует, сам является находкой» начнёт краснеть в дереве, где каталог существует после прогонов:
`Path.exists` не знает про `.gitignore`. Поэтому мы бы выбрали первое; второе требует научить стража
различать «цитата прошлого» и «claim об артефакте», а это уже изменение контракта стража.

## F-5 (жёлтая). `check-readme.py` обещает весь `docs/`, а видит только верхний уровень

Докстрока `lab/check-readme.py` говорит «every Markdown file under docs/… Round packs, syntheses and
audits included», а `DOCS.glob("*.md")` смотрит только `docs/*.md`. В `docs/interop/` лежат три
Markdown-файла, которые этот страж не проверяет никогда. Сейчас они связаны с README, поэтому
зелёно; но обещание шире механизма. Правка — `rglob("*.md")` и сверка по относительному пути,
а не только по имени файла (иначе два `README.md` в разных каталогах неразличимы), либо сузить
докстроку до верхнего уровня.
